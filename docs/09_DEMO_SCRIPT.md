# Demo Script — HireLens

## Core message

> AI는 근거를 찾고, 사람은 결정합니다.

## Demo length

Target: 4–5 minutes.

## Pre-demo setup

- one backend-engineer job,
- one raw job description containing an ambiguous phrase and one concrete technical criterion,
- approved scorecard version,
- 20 synthetic resumes,
- at least one `SUPPORTED`, `PARTIAL`, `NOT_FOUND`, `HUMAN_ONLY`, and failed document case,
- recruiter and hiring-manager demo users,
- reset complete,
- model quota verified,
- offline fallback prepared.

## Scene 1 — Problem in 30 seconds

Say:

> 공고당 약 200명이 지원하지만 실제로 보는 건 약 40명입니다. 나머지는 접수 순서와 담당자의 시간 때문에 검토되지 않습니다. HireLens는 합격자를 대신 뽑지 않습니다. 모든 지원자를 검토 가능한 상태로 만들고, 판단 근거를 남깁니다.

Show the dashboard count and the human-only message.

## Scene 2 — Make the judgment criteria explicit

Open the raw job description.

Show:

- “커뮤니케이션이 좋은 분” → resume judgment is inappropriate → `INTERVIEW_ONLY`
- “Kubernetes 운영 경험” → clarify what operational level counts.

Approve the scorecard.

Say:

> AI가 기준을 확정한 것이 아니라, 현업 리더가 AI 초안을 검토하고 승인했습니다.

## Scene 3 — Process every resume

Upload or open the preloaded batch.

Show:

- total 20,
- completed,
- analyzing,
- `NEEDS_OCR`,
- failed/quarantined if present.

Say:

> 한 파일이 실패해도 나머지는 계속 처리되고, 접수 순서 때문에 사라지는 지원자가 없습니다.

## Scene 4 — Inspect source evidence

Open a candidate detail.

Show:

- criterion,
- status,
- exact quote,
- page number,
- uncertainty,
- suggested interview question,
- source PDF page.

For `PARTIAL`, say:

> 사용 경험은 보이지만 직접 운영 범위는 이력서만으로 확정하지 않습니다.

For `NOT_FOUND`, say:

> 경험이 없다고 단정하지 않고, 제출 자료에서 근거를 찾지 못했다고 표시합니다.

## Scene 5 — Human decision and record

Open the 60-second review card.

Select a decision and reason.

Show the audit timeline with:

- scorecard version,
- model/prompt version,
- reviewer,
- timestamp,
- decision reason.

Say:

> 최종 판단은 사람이 했고, 왜 그렇게 판단했는지가 다음 채용에도 남습니다.

## Final line

> HireLens는 Workday를 작게 복제한 것이 아닙니다. 기존 ATS가 놓치는 판단 기준, 원문 근거, 의사결정 기록을 하나의 흐름으로 연결합니다.

## Do not claim

- AI accuracy is perfect.
- The system is production compliant.
- The model predicts good employees.
- Business target improvements are already proven.
- Real customer data was used.

## Failure fallback

If live AI is slow:

1. use preprocessed synthetic runs,
2. disclose that results were generated by the same contract in advance,
3. still demonstrate source validation and human decision live.

If PDF rendering fails:

- show extracted page text and evidence hash,
- use prepared screenshot only as a fallback,
- do not pretend the live path succeeded.
